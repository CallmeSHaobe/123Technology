## `gregtech`（含扩展注册到同一 `gt.blockmachines` 的机器）

- 以 5.09.54.265 缓存 sources.jar 的注册、构造和 ID 表为准；引文行号均对应此版本。现有 [开发运行日志](<../run/client/logs/fml-client-latest.log#L9474-L9485>) 同时记录 `gregtech`、`bartworks`、`tectech`、`GoodGenerator`、`miscutils` 从同一个 dev jar 加载。这里仅审计物品与 metadata，不把流体 registry 字符串算入。
- `n` 代表原配方实际数量，**不要改变 0 数量催化输入、重复槽位、NBT、通配值或 `setStackSize`**。`ItemList.get(n)` 会经过矿辞统一；严格保持注册堆栈时，复制其模板（`GTUtility.copyAmountUnsafe(n, ItemList.X.getInternalStack_unsafe())`，不对模板原地改动），并在当前运行环境核对物品、meta 和 NBT。对静态 `ItemStack` 字段同理先复制。极大数量仍使用原外层数量表达式。见 [ItemList.java:3483](<https://github.com/GTNewHorizons/GT5-Unofficial/blob/5.09.54.265/src/main/java/gregtech/api/enums/ItemList.java#L3483>)。
- 生成材料表中的 `OrePrefixes` / `Materials` 是从具体物品编码推导的对应关系，不保证 `GTOreDictUnificator.get(prefix, material, n)` 选回同一个物品。必须精确保留原物品时，元数据 `<32000` 可按同一实体 `new ItemStack(MetaGeneratedItem0X.INSTANCE, n, 原前缀槽位 × 1000 + Materials.M.getId())`；这里槽位按原 meta 整除 1000。注册算法见 [MetaGeneratedItemX32.java:52](<https://github.com/GTNewHorizons/GT5-Unofficial/blob/5.09.54.265/src/main/java/gregtech/api/items/MetaGeneratedItemX32.java#L52>)。导体、管道表出的矿辞是已注册候选；若不能确认统一结果，可保留原 ID，用 `GregTechAPI.METATILEENTITIES[id].getStackForm(n)`（初始化完成后先确认不为 `null`）而不改变配方的选择器类型。
- 对 `Casings.X` 使用 `new ItemStack(Casings.X.getBlock(), n, Casings.X.getBlockMeta())` 或显式复制数量；**此版 `Casings.X.toStack(n)` 实际把数量固定为 1**，见 [ICasing.java:55](<https://github.com/GTNewHorizons/GT5-Unofficial/blob/5.09.54.265/src/main/java/gregtech/api/casing/ICasing.java#L55>).
- `RecipesMain.getGM(meta, n)` 等同 `gregtech:gt.blockmachines`，已展开。`RecipesMAXs.getGM(n, OrePrefixes)` 调用的是现成的材料 API，`n` 不是 metadata。机械扫描剔除注释与 `getGM` 方法声明；动态 wrapper 本体另行注明。
