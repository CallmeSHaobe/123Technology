# 绫波丽：实体与骨骼动画

旧的 `modelAyanami` 装饰摆件已从正常获取途径退役：不再出现在创造栏和 NEI，也不能再通过装配机制作。为了兼容旧存档，原注册 ID 和已有摆件保留。新的绫波丽玩法从「未知的 克隆仓」开始。

## 实体原型

可从「未知的 克隆仓」唤醒；调试也可用 `/summon 123technology.Ayanami`。没有刷怪蛋。NPC 不会自然生成，也不会因玩家离开而消失。它会在附近闲逛、看向玩家。准星对准实体后按 **T** 打开 MUI2 半透明输入条，**回车**发送，**Esc** 关闭；键位可在 Minecraft「控制」里修改。没瞄准时，T 仍打开原版聊天。丽的回复以不透明气泡显示在头顶，12 格内的玩家不用打开面板也能看到。发出消息后提前关闭面板，只要仍在她 8 格内，纯文本回复仍会出来；关闭后不会执行物品动作。只有丽的台词公开，问题原文和历史不会广播，不过她的回复可能复述聊天内容。输入条打开期间，她会停止闲逛，身体和视线朝向正在和她对话的玩家，不会被路过的其他玩家分散注意力；关闭输入条或离开范围后恢复平常的行为。丽被怪物攻击时会优先反击。

NPC、摆件和物品共用模型。站立时双脚微分。步态按移动距离推进，约每 0.70 方块完成左右各一步，腿部最大前后摆幅为 17°；行走时双臂前后轻摆，停下后自然下垂。袖套与主臂共轴，绕同一肩轴转动。头部平时转向 8 方块内最近的可见玩家，两只眼珠各自朝目标移动。没有目标时眼珠保持中立。NPC 会随机每隔 40–70 个客户端游戏 tick 眨眼一次，闭合和重新睁开共 5 tick；摆件和物品不眨眼。

显式关键帧优先控制对应骨骼，例如挥手时右臂按预设播放，腿仍可行走。不管头动不动，眼珠只在眼白范围内滑动；目标移动到头的后方时回到中立。

## 克隆仓、物品和闲逛行为

- 任务书奖励物品：`123technology:ayanami_clone_pod`，数量 1，元数据 0。管理员可用 `/give @p 123technology:ayanami_clone_pod 1 0` 测试。**模组不改任务书**。任务文案可写「一次外出时，你偶然发现了一座封闭的舱体。铭牌已经磨损，维生指示灯仍然亮着。」
- 新放置的克隆仓占上下两格，外墙为不透明灰玻璃，门朝向摆放者。右键任一半可启动；门前须有实心地面、两格净空且无液体或碰撞。成功才成为空仓（物品元数据 1），拆下重放保持空仓。旧版已放置的一格仓可拆下重放变成两格，唤醒状态不变。初醒气泡优先由 AI 生成，失败时仍可本地显示。
- 手持物品右键交给她，每次送一件。手上有东西时，她会放入最多八格的个人物品栏；物品栏随存档保存。送出的物品归丽，可以使用、吃掉或丢到地上；还在她手里或包里的，可以由原赠送者空手右键取回。玩家物品栏没空间时保留原物品；开启 `doMobLoot` 且未被插件取消时，她死亡会掉出物品。
- 亲手递给她真正的朗基努斯之枪才会触发首次觉醒：停步、调整握姿、抬眼并对赠送者说一句话。觉醒只播放一次并随实体保存；不会触发武器的投掷。之后再次递枪只是简短回应。
- 无人交谈时偶尔在走路途中自言自语，用附近玩家可见的气泡，不进私人历史。拾取只在单人整合服务端且仅房主在线时运行：行走中每 100 tick 最多判定一次，概率为 1/200，只在手空时捡取靠近、已放置至少 200 tick、无归属和投掷者的掉落物之一，留在手里由房主取回。专服 / 有其他玩家在线时不自动拾取，以免绕过整合包的领地和掉落物规则；主动交接仍可用。

## 互动台词与自言自语

接收和归还物品、开仓初醒、朗基努斯觉醒和再次递枪，以及附近有人时的闲逛自言自语，会优先使用已配置的 AI，按玩家的游戏语言生成一句台词。不需要打开对话框。同一场自言自语按语言合并请求，并限制并发；没有合适的听众时不发送请求。未启用、没有密钥、没有权限、繁忙、失败或约三秒还没返回时，继续用模组的本地台词。按钮、状态提示和报错仍使用固定翻译。

自动台词使用当前对话端点和 `operatorsOnly` 权限，只发送人设、固定事件提示和听众的语言代码；不发送背包、物品名称、玩家名、坐标或私聊历史。不计入玩家对话框的 Token 用量，也不写入私聊历史，但服务商仍可能计费。物品交接、剧情和动画不等 API。

## 丽自己的物品与 AI 操作

玩家主动发消息时，丽能看到自己手上和八格个人物品栏中的物品 ID、元数据和数量；这与是否共享**玩家**物品栏无关。可以说「你带了什么？」「把剑拿在手里」「吃一个苹果」「喝牛奶」「把这件东西丢到地上」。每条回复最多尝试操作一件自己的物品；如果东西已经被取回、换位、消耗，或对话已经结束，旧回复不会动到别的物品。闲逛自言自语和自动剧情台词不执行物品操作。

「拿在手里」会与她的右手物品交换；「吃」只处理受支持的原版食物，会恢复生命值；「使用」只处理牛奶及支持的原版非喷溅药水，容器留在原格；「丢弃」会生成一个可捡回的地面物品。不会操作玩家的背包，也不会模拟对准方块、其他玩家或实体的点击。

在聊天框说「挥一下你手里的东西」或「右键使用你手里的东西」可请求一次点击。左键默认只空挥，右键可直接吃/喝支持的消耗品。服主可在 `ayanami_dialogue.nativeItemClickItems` 填入信任的物品注册 ID，以便允许该物品的 Forge 挥动或原生空中右键钩子。默认列表为空；第三方钩子本身可以产生世界效果，只应添加你信任并测试过的道具。右键在丽的位置以独立的无 OP 模拟玩家执行，不使用任何真实玩家的背包。

丽还能读取右手物品的显示名、耐久、使用姿势和物品声明的最大使用时长，让 AI 判断单击还是按住。经服务端允许的物品，可以尝试按住右键最多 20 游戏刻然后松开；不是重复发送点击。关掉对话、进入战斗或离开范围会中断按住。显示属性仅供参考，不代表第三方物品必然兼容。模拟使用只带当前手上的一件物品，不会读取个人物品栏中的弹药，也不会自动点方块或实体。操作失败会提示原因，而不是播放声称成功的台词。

## 敌对生物与反击

常见、原本就主动攻击玩家的怪物也能发现并攻击绫波丽；苦力怕及使用同类自爆 AI 的怪物不把她当目标。这类怪物的自爆不会伤到或击退她，TNT 和恶魂火球等普通爆炸不受影响。不会把已在交战的怪物硬拉离玩家，也不默认激怒中立生物。使用专用索敌或 Boss 逻辑的第三方怪物不保证兼容。

丽受到合格敌对生物的伤害后会自动追击并持续还手，不需要指令或 API。只追击实际伤到她的怪物，不打玩家、宠物或普通动物；同一目标不会因追击时间或距离自动过期。双方之一死亡、目标离开世界或卸载后结束；遇到墙、悬崖或无法寻路时不会传送或穿墙。手持普通近战装备时使用武器加成，空手也能反击。手持朗基努斯时会加速冲向敌人，以突刺一击击杀普通怪物；不投掷、不绕过模组的伤害免疫或保护。

## 倒地与复活

受到致命伤后，丽会向后倒下，停止对话、使用物品和战斗。倒地时眼睛不再追视或眨眼，瞳孔放大并失焦。约 5 秒后完成起身并恢复满血，短暂免疫普通伤害；不会掉落手持物或个人物品，也不会生成一个新的实体。倒地进度随存档保存。

## 配置外部 AI 对话

新配置的 `enabled` 默认为 `true`；旧配置中显式写的 `false` 保持不变。对准绫波丽按 **T → 设置**，输入以 `/v1` 结尾的 API 基址（也可填写完整 Chat Completions URL）、模型和服务商签发的 **API Key**，然后保存。Key 输入时用星号遮挡，保存后不回显；只改同一地址的模型或开关时，Key 留空即可。密钥绑定完整 API 地址，更换地址不会把旧密钥发送给新服务。旧版本环境变量不再读取，升级后请在游戏里重新录入一次。

单人房主可以录入。专用服务器由服主在 `config/123technology.cfg` 的 `ayanami_dialogue` 分类中设置 `allowInGameApiEditing=true` 并重启后，才允许通过已经启用原版加密的正版连接（服务器 `online-mode=true`）的 OP 录入；离线或未加密的多人连接不会提交密钥。

API Key 不写到普通配置，而是以 AES-GCM 加密保存在服务器的 `config/ayanami-credentials`，主密钥与密文分开存放，并限制到运行服务器的系统账户。能同时读取两份文件的人仍可解密，不要把该目录发给他人或放进公开备份。只向 `/chat/completions` 发送带 Bearer 认证的请求，不用网页聊天、网页登录或浏览器会话。**不要把密钥输入普通对话栏或写入 URL。**

### 模型与深度思考

在「模型预设」下拉菜单选择模型，或在「模型」输入框填写服务方的精确 ID。预设只填写模型 ID，不修改服务地址或密钥；切换服务商时须自行填写对应地址和 Key。新配置使用 `deepseek-flash`，不会覆盖已有的模型设置。模型是否可用也取决于 API 账户权限。

| 服务 | `endpoint` | `model` 预设 | 可选推理 |
| --- | --- | --- | --- |
| [DeepSeek 官方](https://api-docs.deepseek.com/quick_start/pricing.md) | `https://api.deepseek.com/chat/completions` | `deepseek-flash`（V4.1 Flash）、`deepseek-v4-pro` | 开／关／模型默认；低／高／最高 |
| [OpenAI 官方](https://developers.openai.com/api/docs/models) | `https://api.openai.com/v1/chat/completions` | `gpt-6.2-sol`、`gpt-6.2-astra` | 不能关闭；低／中／高／极高／最高 |
| OpenAI 官方 | 同上 | `gpt-6-luna`、`gpt-4.1-mini` | Luna 可关；4.1 mini 不支持推理设置 |
| 其他兼容服务 | 提供方给出的 HTTPS `/v1` 基址或完整 `/chat/completions` 地址 | 提供方给出的模型 ID | 默认省略推理参数；仅当服务文档支持时手动选 DeepSeek 或 OpenAI 协议 |

「自动识别」只对已知官方地址与模型组合启用对应协议；「不发送参数」让服务端用模型默认行为，不等于强制关闭思考。DeepSeek 使用 `thinking.type` 和 `reasoning_effort`；OpenAI 使用 `reasoning_effort`，已知推理模型自动改用 `max_completion_tokens`。参考 [DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode.md) 和 [OpenAI 推理文档](https://developers.openai.com/api/docs/guides/reasoning)。高强度可能更慢、费用更高；如果没有输出最终台词就用完预算，降低等级再试。气泡只显示最终回答，不显示推理过程。

例如 `https://gateway.example.com/custom/v1/` 会解析为 `https://gateway.example.com/custom/v1/chat/completions`。等价的基址与完整地址共享同一个密钥绑定；换成不同服务不会复用旧密钥。这只支持兼容 Chat Completions 的供应商，不代表支持仅提供 Responses 或其他协议的服务。

仅在信任本机代理或本地模型时设置 `allowLoopbackHttp=true`；这样才可使用 `http://127.0.0.1:端口/v1/chat/completions`。本机接口也必须配置 API Key。不会跟随 HTTP 跳转。

外部对话默认只对单人房主或服务器 OP 开放。只有接受相应隐私与费用风险时，才把 `operatorsOnly` 改为 `false`。输入栏上方显示双方合计最近六条（最多三个完成的问答），较长内容可以滚动。关闭后重开仍可看到；历史按玩家与绫波丽实例隔离，只保存在当前服务端运行内存，不写存档，重启或修改 API 设置后清除，缓存满会淘汰最久未用的会话。每次手动聊天请求发送人设、这六条、当前输入和现场摘要。现场摘要包括昼夜、天气、维度类别、附近可见方块及可识别的 GT 机器类型，以及当前玩家主物品栏和快捷栏的物品 ID／数量。服主可设置 `sharePlayerInventory=false` 关闭背包共享；不发送玩家名、坐标、箱内数据、完整物品 NBT 或存档。只在玩家主动发送对话时收集和发送，提供方可能保留收到的文本。

「回复长度上限」可设为 32–1800 字符，默认 900。它限制后续请求的可见台词长度，不会清空历史，也不是计费 Token 上限。模型会收到长度提示，超过上限的文字会在服务端截断。输入框下方显示服务商为上次成功回复报告的输入、输出和总 Token；不支持或缺失的字段不估算。推理 Token 可能已计入输出，输入也可能包括提示词和对话历史。

绫波丽的剧情人设以 UTF-8 Base64 保存于 [ayanami-persona.b64](<../src/main/resources/assets/123technology/dialogue/ayanami-persona.b64>)。服务端组装首个对话请求时自动解码，之后把解码结果作为每次请求的 `system` 消息。Base64 只避免资源里直接出现明文，不是加密；API 提供方会看到明文，不要写入密钥或真实敏感数据。人设提到的剧情事件并不会因此被实装。

模型可以建议 `点头`、`环顾`、`挥手`，服务器只在 NPC 处于站立预设时按 `gestureChancePercent`（默认 40）随机触发一次，然后回到站立。设置为 0 可禁用。模型也可建议看向当前请求的一个现场目标，服务器会重新验证该方块仍在范围内、可见且未变化。模型不能提交坐标、执行命令或修改世界。

本地验证：`.\gradlew.bat ayanamiDialogueCheck ayanamiKeyVaultCheck` 使用本机模拟服务和临时凭证库，不消耗 API 额度。实机检查建议：保存密钥后重开设置确认不回显；观察空闲、输入、等待和退出四个阶段的移动与视线；两名有权限的玩家同时打开窗口时确认不会抢走她的视线。

## 编辑关键帧

在 [Ayanami.rig.json](<../src/main/resources/assets/123technology/models/Ayanami.rig.json>) 编辑关键帧，重启客户端预览：

- `bones` 按父骨骼先于子骨骼排列。`pivot` 是站姿 OBJ 坐标系中的轴心，单位是方块。`meshes` 是骨骼驱动的 OBJ 分组。子骨骼继承父骨骼的变换。眼珠节点上的 `pupilTravel` 依次记录最大横向偏移、最大向下偏移和眼面坡度 `dZ/dY`；可用 `pupilUpTravel` 单独设定最大向上偏移。
- `clips` 按动作 ID 索引。轨道对应骨骼，帧格式是 `[tick, x, y, z]`；后三项是相对原站姿的旋转角度（度）。帧时间须从 `0` 递增到 `duration`，首尾角度相同以便循环。没有轨道的骨骼不额外旋转。
- `standing` 保持空轨道。新增可切换的预设还须更新 [AyanamiAction.java](<../src/main/java/com/newmaa/othtech/common/blocks/AyanamiAction.java>) 和语言资源。

[Ayanami.obj](<../src/main/resources/assets/123technology/models/Ayanami.obj>) 是游戏实际加载的网格，含关节分组、修整过的袖口及裙衬；[Ayanami.bbmodel](<../src/main/resources/assets/123technology/models/Ayanami.bbmodel>) 的摆姿和轴心与游戏内站姿不同，不能直接覆盖此网格。当前有六根身体骨骼（躯干、头、左右整臂、左右整腿），以及两根独立眼珠节点，没有肘膝蒙皮。挥手由整条手臂转动实现；调整肩轴时，须让轴心同时位于袖口和躯干网格内。

离线回归：`gradlew.bat ayanamiRigCheck`。实机检查建议：放置摆件并确认站姿；依次切换各动作；转向放置后确认动画跟随朝向；退出重进后确认动作保留。
